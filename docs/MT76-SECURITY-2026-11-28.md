# mt76 security audit and patch bundle

The bundle targets mt76 `0936617dc529ff9da0385221d3fa6de732231177`. The audit reviewed the installed package patches and official mt76 history through `10be1829783cff271f5e81111258387a72b5192b`. [Driver baseline](https://github.com/openwrt/mt76/commit/0936617dc529ff9da0385221d3fa6de732231177) · [Upstream review endpoint](https://github.com/openwrt/mt76/commit/10be1829783cff271f5e81111258387a72b5192b)

## Findings and fixes

| Area | Changes |
| --- | --- |
| Receive authentication | Return group management frame authentication to mac80211 for four driver families. Track replay counters by group key and traffic identifier, validate the additional AES data ciphers, and drop replayed decapsulated aggregates before delivery. [Management frames](https://github.com/openwrt/mt76/commit/4938ad1) · [Group replay tracking](https://github.com/openwrt/mt76/commit/f79265b) · [Decapsulated frames](https://github.com/openwrt/mt76/commit/3115dbc) |
| Receive buffer and station lifetime | Drop partial aggregates when their station or PHY disappears. Validate RX segment lengths and discard incomplete NPU packets. Preserve the existing first-subframe check and decode radiotap offsets in common receive code. [Aggregate lifetime](https://github.com/openwrt/mt76/commit/6a2f145) · [NPU reassembly](https://github.com/openwrt/mt76/commit/a801adb) |
| Scan and firmware buffers | Bound the combined scan information elements, the MT7925 beacon payload, and the MT7996 firmware discovery template. [Scan bounds](https://github.com/openwrt/mt76/commit/2e14ffb) · [Beacon buffer](https://github.com/openwrt/mt76/commit/6a9b493) · [Discovery limit](https://github.com/openwrt/mt76/commit/4998112) |
| Reset, interface teardown and TWT | Serialize list cleanup, drain work before removal, defer freeing MT7925 interface links until RCU readers finish, and use full-width TWT arithmetic on MT7996. The MT7915 package already carries its full-width TWT fix. [MT7925 RCU](https://github.com/openwrt/mt76/commit/52b8053) · [MT7915 reset](https://github.com/openwrt/mt76/commit/ea9165b) · [MT7996 TWT](https://github.com/openwrt/mt76/commit/eab12d5) |

The `opsource-temp` source branches both move to mt76 package release 6. They retain their driver pin, firmware mirror hash, and branch-specific patch sets. The 60 new patches carry upstream provenance and the NPU guard from the earlier local audit. The `main` branch also gains the MT7615 header fix already present in `test-flight`.

This is a host-driver audit. MediaTek firmware CVE coverage remains unverified. [MediaTek Wi-Fi advisory](https://www.cve.org/CVERecord?id=CVE-2025-20737)

## Install on an unpatched source tree

Use Python 3.9 or later, Git, and `patch` on Linux or macOS. Extract this bundle, then run the installer with the root of an OpenWrt or ImmortalWrt checkout. OpenWrt `main` and ImmortalWrt `master` were tested at the commits below. The installer checks the package pin, preserves the distro patches, and applies the combined series in a temporary source tree before installing its 71 patches and incrementing `PKG_RELEASE`. [OpenWrt package](https://github.com/openwrt/openwrt/tree/5fb8f35f600bd62eae98e20783343972ecfd96ed/package/kernel/mt76) · [ImmortalWrt package](https://github.com/immortalwrt/immortalwrt/tree/73bc086a62f951d96e5d7404f04c4d73e141cad2/package/kernel/mt76)

```sh
python3 install.py verify --root /path/to/source
python3 install.py apply --root /path/to/source
python3 install.py status --root /path/to/source
```

For offline use, append `--source /path/to/mt76-git` to `verify` and `apply`. The local repository must contain the pinned commit. The 25.12 branches use mt76 `39c960c3`, outside the scope of this bundle. [OpenWrt 25.12 recipe](https://github.com/openwrt/openwrt/blob/openwrt-25.12/package/kernel/mt76/Makefile) · [ImmortalWrt 25.12 recipe](https://github.com/immortalwrt/immortalwrt/blob/openwrt-25.12/package/kernel/mt76/Makefile)

Use `python3 install.py rollback --root /path/to/source` to remove the installer's patches and restore the prior package release. Rollback checks the installed files and release first. After applying or rolling back in a configured build tree, rebuild the driver.

```sh
make package/kernel/mt76/clean
make package/kernel/mt76/compile V=s
```

In either `opsource-temp` review branch, `scripts/install-mt76-security.py` provides the same installer for a separate clean source checkout.

## Verification

- Both `opsource-temp` patch series applied with zero fuzz to the checksum-verified OpenWrt mt76 archive. Source checks passed for Linux 6.18.65 and 7.3.6. The existing suites reported 101 tests on `main` with 10 skipped, and 154 on `test-flight` with 22 skipped. There were zero failures.
- Both prepared driver trees passed source-extracted ASan and UBSan checks for A-MSDU validation, NPU RX reassembly and cleanup, and group and pairwise replay counter isolation.
- On the two official package checkouts, the installer passed verify, apply, repeat apply, and rollback. Rollback restored each checkout to its initial clean state.
- Full Linux module compilation and physical device behavior are separate validation steps. The source checks and host test harnesses covered the code paths above.
